# SwitchBotリモートボタンを呼び鈴にする

「SwitchBotの機器を操作する機能」と「物理リモートボタンの押下を受け取る機能」は別です。この手順は後者です。

## できること・必要なもの

丸・凹ボタンの押下をiPadがBluetoothで読み取り、RoomCanvasのポップアップとWebhookで知らせます。BLE受信だけならSwitchBot Token / SecretやHubのAPIは使いません。インターネットはWebhook送信に必要です。

- SwitchBot Remote（丸・凹のあるリモートボタン）
- BluetoothをオンにしたiPadとRoomCanvas
- 設定済みで、画面からの呼び出しが成功するWebhook

**「リモートボタン５」は開発時のユーザー設定名で、型番ではありません。** 名前を同じにする必要はありません。Remote mini、Universal Remote等の別製品まで対応を保証していません。

既にSwitchBot側で別の操作を割り当てているボタンを押すと、その操作も動く可能性があります。試験前にSwitchBotアプリで割り当てを確認してください。RoomCanvasはその設定を変更しません。

## A. 通知先だけを先に確認

1. RoomCanvasの設定でデモモードをオフ。
2. 「呼び出し通知 / Webhook」で送信形式とURLを保存。
3. 「その他」ページの「呼び出す」を押す。
4. 通知先で受信できたら次へ。Discord以外の手順は[こちら](WEBHOOKS.md)。

## B. 自分のリモートを見つける

1. リモートをiPadの近くに置く。
2. 設定 → 呼び出しボタン → リモートボタンの設定を開く。
3. 「機器を選択・受信ログを確認」を開く。
4. 初回はBluetoothを許可。サービスUUIDは空欄、背景検証はオフのまま「スキャン開始」。
5. 「リモート候補」一覧が出るまで待つ。
6. リモートの丸を押す。少し待って凹も押す。
7. 候補の「データ末尾」が押下に応じて変わる機器を探してタップする。

候補の12桁英数字は、自分の機器を区別するための識別子です。説明書の例や他人の値を入力するものではありません。Bluetooth上ではSwitchBotアプリの名前が見えず「名称なし」と出ることがあります。

複数候補がある場合は1台ずつ操作します。リモートの電池を一時的に外して受信が止まるかを照合する方法もあります。表示一覧は過去の受信も残るため、一覧から消えることではなく受信回数の変化を見てください。

## C. ボタン判定を確かめる（まだ通知はオフ）

1. 対象を選び、「ログをクリア」。選択は残ります。
2. 数秒待ち、最初の受信を基準値として取得させる。
3. 丸を約10秒間隔で5回押す。「検出：丸」が5増えるか確認。
4. 凹も同様に5回。「検出：凹」が5増えるか確認。
5. 最後の検出から30秒間何も押さず、回数が増えないか確認。

「受信○件」は押下回数ではありません。同じ広告を何度も受け取るためです。検出回数だけを比較してください。「押した：丸／凹」はログ用の手動マーカーであり、リモートの代わりにはなりません。

## D. 呼び出しを有効にする

1. 診断画面を閉じ、通常のリモートボタン設定で「呼び出しを有効にする」をオン。
2. ダッシュボードの「呼び出し待受中」を確認。
3. 丸を1回押し、ポップアップと通知先を確認。
4. 30秒以上空け、凹でも確認。

両ボタンが呼び出しに使われます。対象と有効状態は保存され、次回のアプリ起動でも再開します。別の機器を選ぶと通知がオフになるため、有効にし直してください。

## 常設するとき

アプリを前面表示し、電源に接続して使います。アクセスガイドが便利です。画面ロック・他アプリへ移動すると呼び出しは休止します。前面復帰後は最初の広告を基準値にするため、休止中の押下は通知しません。強制終了・再起動後にアプリ自体を自動起動する機能はありません。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 全機器の受信が0件 | iPadのBluetooth、アプリへの許可、スキャン開始 |
| 候補がない | リモートを近づけて押す、電池、製品の違い。未対応機種の可能性あり |
| 押下回数が合わない | 正しい候補か、複数回押していないか、電波環境。通知を有効にせず診断 |
| 検出するが通知しない | 通知の有効設定、デモモード、Webhook保存、前面表示、30秒制限 |
| 電池交換後におかしい | 一度停止して再開し、再度Cの試験を行う |

解決しない場合はJSONログを書き出せます。ただし機器識別子や周辺機器情報を含みます。生ログを公開Issueへ貼らず、必要箇所を匿名化してください。

BLE形式は公開仕様でなく実測に基づく実装です。別ファームウェア・長押し・連続操作・電池交換時の挙動は個別に検証してください。
